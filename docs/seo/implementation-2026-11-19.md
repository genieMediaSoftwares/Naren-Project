## Changes implemented

1. **Metadata and headings.** Kept a unique title and description for each of the
   eight core pages and 18 mapped articles. Shortened the two long article titles.
   Added explicit article descriptions, clear service/location H1s and consistent
   article H1/schema headlines. The database article title and body are unchanged.
2. **Internal discovery.** Added visible breadcrumbs and matching BreadcrumbList
   schema. Existing articles link to up to four relevant published guides, with
   self-links, drafts and missing articles excluded. The services hub links to its
   published TIFFA/NT guides. Article cards link through their titles as well as
   their existing calls to action.
   Homepage service headings also link directly to their existing service sections.
3. **Service targeting.** Expanded the existing services page with TIFFA, NT,
   abdominal and Doppler service summaries and appointment/fee enquiry guidance.
   No diagnostic instructions, screening guarantees or medical outcome claims
   were added. No new service routes were created.
4. **Contact and Gallery.** Added practical visit information, relevant links,
   descriptive gallery captions and clear headings. Existing forms and booking
   scripts retain their controls and behavior.
5. **Images.** Added responsive WebP sources for 33 explicitly public images,
   retaining original fallback URLs and full-image aspect ratios. Included
   intrinsic dimensions, eager/high-priority hero loading and lazy loading for
   secondary images. Article readers can open the original full-size image.
6. **Cache delivery.** Generated content-addressed image/CSS filenames and a small
   PNG favicon. Only these versioned assets receive immutable caching; originals
   and ordinary unversioned assets keep their existing policy.
7. **Fonts.** Combined the two existing Google Fonts stylesheet requests while
   preserving their fonts, weights, swap behavior and preconnections.
8. **Verification.** Added offline regression coverage and a test settings module
   that uses an isolated in-memory database and email backend.

The 33 original images total 26,673,561 bytes. Their largest generated display
variants total 3,502,664 bytes, about 87% less. This is an aggregate asset comparison,
not a claim that a page or the live site is 87% faster. Smaller viewport variants
are also available. Originals remain unmodified and available as fallbacks.

| Area | Source |
| --- | --- |

| Responsive additions | `website/static/css/responsive.css` |
| Versioned display files and manifest | `website/static/seo-images/`, `website/static/seo-assets/` |
| Immutable-cache callback | `website/static_cache.py`, referenced in project settings |
| Reproducible asset build | `tools/build_seo_images.py` |
| SEO and delivery regression checks | `website/test_seo.py` |
| Safe offline test configuration | `naren_ultrasound/test_settings.py` |

For the 18 mapped articles, `ARTICLE_DESCRIPTIONS` is the explicit presentation
source. `post.meta_description` remains the fallback for unmapped articles. Editing
only the CMS description of a mapped article does not override that mapping.

Run `python -B tools/build_seo_images.py` after changing source CSS/images and before
the normal static build/deployment. The script performs no network requests or
database operations. It reads the static image directory and an explicit list of
already-public blog/doctor images; it does not scan private patient uploads or
blog photo galleries. New unlisted uploads retain the original-image fallback
until an approved source is added to the build list.

Generated filenames depend on file contents, so a changed image or stylesheet
gets a new URL. Preserve original media and page URLs. Do not overwrite the content
of an existing versioned URL with unrelated bytes. WhiteNoise serves these files
through the existing static pipeline; no runtime image generation is needed.
